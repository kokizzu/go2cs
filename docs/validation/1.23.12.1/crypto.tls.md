## Disclosed divergences

A disclosed divergence is a specific Go assertion the managed CLR *provably cannot* satisfy — not
a skipped test and not a tolerance. Each one is pinned by exact failure signature in the package's
hand-owned [`go2cs_test_disclosures.json`](https://github.com/ritchiecarroll/go2cs/blob/master/src/core/crypto/tls/go2cs_test_disclosures.json);
a disclosed test that fails any *other* way is still a hard mismatch.

| Test | Class | Pinned reason |
|:--|:--|:--|
| `TestBogoSuite` | `host-limit` | The test delegates to BoringSSL's own test runner, spawned as `go test .` in the boringssl module — a child that carries Go's default 10-minute test-binary deadline, which neither the package's code nor the host controls (the test passes no -timeout, in either language). Inside that wall the runner spawns the shim once per case — 5,481 spawns in this configuration — and the shim IS the converted test host: a framework-dependent apphost whose process start (hostfxr resolution, CLR startup, JIT over the converted-stdlib closure) measures 3.30 s where Go's statically linked test binary starts in 0.038 s. That ~87x is structural to the deployment shape — it is what the artifact IS, not how far an implementation has got. Measured 2026-08-18: the runner reaches ~267 of 5,481 cases at its wall even with 16 parallel shim workers — a ~20x shortfall no deadline the test can express would close — then exits without writing its results JSON, which selects exactly the failure arm this signature pins. The TLS interop capability itself is not in question and is proven by value in the same suite: with `-bogo-filter Client-Verify-ECDSA-TLS1` the converted host completes a TLS handshake with certificate verification against BoringSSL as the peer, PASS in 14 s end to end including the module download and runner build. Same self-retiring texture as os/exec's relocatable-single-file entries: publish the host with fast startup (ReadyToRun/AOT) and this row starts passing, the disclosed count stops matching, and the sweep fails until the entry is removed. |
| `TestCertCache` | `codegen-liveness` | The test nils its own local and then asserts, from inside the same still-running frame, that the object it dropped has become collectible: `certA = nil; runtime.GC()`, then a four-second poll for the cache entry's reference count to fall from 2 to 1, ending in this t.Fatal. The finalizer that would decrement it works — runtime.SetFinalizer is the hand-owned ConditionalWeakTable-and-sentinel bridge, runtime.GC() is Collect then WaitForPendingFinalizers then Collect, and sync's banked TestPoolGC measures 98 of 100 objects finalizing on the first try — but `certA, err := cc.newCert(p.Bytes)` is a two-result call whose results materialize an address-exposed frame temp, and an address-exposed slot is not lifetime-tracked: the CLR reports it live for the whole method, so the activeCert stays reachable until TestCertCache RETURNS and the count cannot fall while the test is looking. Measured to fail at the FIRST check identically in a separately built optimized Release host, so it is the CLR's GC-info conservatism rather than the non-optimizing JIT's frame-wide liveness. Same mechanism, and the same non-satisfiable-at-any-layer-go2cs-owns conclusion, as sync's TestOnceXGC and TestPoolGC disclosures. |

`TestBogoSuite` is **host-conditional**: The GO side is decided by network reachability of the pinned boringssl module, which `go test` downloads and builds BoringSSL's own runner from, and by how far that runner gets inside the 10-minute deadline Go's test binary carries by default — so per host and per run the Go baseline passes, expands into its 3,243-row case matrix, or fails.
The row is therefore accepted — and counted as disclosed — in two shapes: `go test` **pass**
with go2cs **fail**, the pinned divergence above; or **both sides failing**, agreement on a host
where the Go premise itself fails. Any movement on the go2cs side still fails the comparison, in
either direction — the pin stays strict on the half that is deterministic.

A disclosed test that fails at its root never reaches its own case fan-out, so the
subtest verdict rows `go test` reports underneath it have no converted counterpart to
compare. Those rows are withdrawn with their disclosed root — none is claimed by the
matched count above:

- `TestBogoSuite` — 3242 verdict rows withdrawn
