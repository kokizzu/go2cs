  1. The toolchain (H1). Install Go 1.23.12 side-by-side, bump x/tools and x/mod as their OWN
     commit with its own CNR, then rebuild the converter -- a toolchain hop invalidates
     go2cs.exe in NO harness predicate, so the build is owed explicitly:
        cd src/go2cs && go build -o bin/go2cs
        go test ./...

  2. The REGEN (H5, H8). Generated artifacts move by conversion, never by edit. Seed the
     staging root FIRST -- an unseeded root gives the hand-own marker nothing to detect,
     emits every whole-file hand-own as a plain .cs, and breaks per-GOOS layout adoption:

        # seed: src/core, src/version.props and docs/validation, mirroring the src/ layout
        # then, single-target (the default windows corpus):
        go2cs -stdlib -comments -go2cspath <staging>/src

        # and the layout-L3 multi-target emission this corpus actually carries:
        go2cs -stdlib -comments -platforms windows/amd64,linux/amd64,darwin/amd64 \
              -platform-stage <stage> -go2cspath <staging>/src

     Delete and re-seed per run; never convert twice into one staging root.

  3. The GATES. converter go test, check-no-regression.ps1, the full behavioral suite,
     go2cs-stdlib.slnx per target OS, and the roster sweep. None is run here.

  4. The JUDGEMENT. The package census (H3), the hand-own .auto differential (H6), the
     golden-drift triage, and the per-row roster re-derivation (H10) -- every roster row
     re-validates from the new release's own test sources, and no substitution can do that.

  5. The CONVERTER TOOL version. That is set-version.ps1's (the winres PE resource), and it
     is independent of version.props. Untouched here on purpose.
